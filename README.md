# 내전 도우미

LoL 내전 참가자를 모아 5:5 팀을 자동으로 짜주는 Discord 봇. 내 PC에서 직접 돌린다.

## 준비

Python 3.9 이상. 저장소 루트에서:

```bash
python3 -m venv venv
venv/bin/pip install -r requirements.txt
```

`.env.example`을 `.env`로 복사해 채운다.

```bash
cp .env.example .env
```

| 항목 | 설명 |
|---|---|
| `DISCORD_TOKEN` | [Discord 개발자 포털](https://discord.com/developers/applications)의 봇 토큰 |
| `RIOT_API_KEY` | [Riot 개발자 포털](https://developer.riotgames.com). 개발용 키는 24시간마다 만료되므로 `/전적등록`이 하루 뒤 실패하면 새로 발급받는다 |
| `DISCORD_GUILD_ID` | 슬래시 명령을 즉시 등록할 서버 ID. 쉼표로 여러 개. 비우면 전역 등록이라 반영에 최대 1시간 걸린다 |
| `ANTHROPIC_API_KEY` | `/오더채점`(음성 대본 채점)에만 쓴다. 비워두면 그 명령만 동작하지 않고 나머지는 그대로다 |

## 실행

```bash
venv/bin/python -m app.main
```

`내전도우미#8506 로그인 완료`가 보이면 성공. Discord에서 `/ping`으로 확인한다.

DB는 저장소 루트의 `war_helper.db`(SQLite) 하나다. 첫 실행 때 자동으로 만들어지고,
이후 기동할 때마다 스키마를 최신으로 맞춘다(`app/main.py` 의 `migrate()`). 별도 설치가
필요 없다.

끄려면 `Ctrl+C`. **봇은 이 프로세스가 떠 있는 동안에만 응답한다** — 내전을 할 때 켜두면 된다.
껐다 켜도 기록은 남고, 진행 중이던 내전의 버튼도 다시 살아난다(`restore_views()`).

Discord 공지로 붙여넣을 사용자용 안내는 [discord_notice.md](discord_notice.md) 에 있다.

### 누가 무엇을 할 수 있나

**전부 서버 인원 누구나 할 수 있다.** 모집 열기·팀 생성·자리 교환·모집 삭제·결과
확정에 권한 제한이 없다. 친목 내전이라 관리자가 자리에 없다고 멈추는 쪽이 더 불편하다.

다만 **결과 확정은 되돌릴 수 없다.** 잘못 누르면 그 내전의 승패가 그대로 남아 내전
승률과 MVP 집계에 들어간다.

### 팀 수정

팀 생성 뒤 메시지에 붙는 **자리를 바꿀 두 명을 고르세요** 메뉴로 누구나 배정을 손볼 수
있다. 고른 두 사람의 팀과 라인을 통째로 맞바꾸므로 팀마다 라인 5개는 그대로 유지된다.
바꿀 때마다 밸런스 점수를 같은 기준으로 다시 계산해 보여준다.

### 사설 전적 기록

`/결과`에 LoL 클라이언트에서 받은 매치 히스토리 JSON([받는 법](#전적-파일-받기))을
첨부하면 승패뿐 아니라 KDA / CS / 딜 / 받은 딜 / 골드 / 와드 / 첫킬 / 첫포탑과 경기
시간까지 저장하고, `/내전전적`의 라인별 지표에 반영한다. 첨부하지 않으면 지금처럼
버튼으로 승리 팀만 고르면 된다.

**파일 하나로 참가자 전원이 기록된다.** 클라이언트가 내주는 기록에는 그 경기 10명이
모두 들어 있어서, 아무나 한 명이 올리면 열 명의 성적이 한 번에 들어간다.

파일 안에 경기가 여러 개 있어도 되고, 참가자 10명이 모두 들어 있는 가장 최근
경기를 자동으로 고른다. 중단된 경기(`endOfGameResult`가 `Abort_`로 시작)는 건너뛴다.

**참가자는 게임이름#태그로 맞춘다.** 클라이언트가 내주는 기록은 `puuid`,
`accountId`, `summonerName` 이 모두 익명화되어 있어 다른 식별자를 쓸 수 없다.
`/전적등록`에 쓴 Riot ID 와 다른 계정으로 내전을 뛴 사람은 **승패만** 기록되고 개인
성적은 비워 둔다. 결과 메시지에 누가 안 맞았는지 알려준다. 못 맞춘 사람이
`MAX_UNMATCHED`(2명)를 넘으면 엉뚱한 경기를 고를 위험이 있어 파일 자체를 받지 않는다.
전원이 들어 있는 경기가 있으면 그쪽을 먼저 고른다.

봇이 짠 A/B 팀과 파일의 승패가 어긋나면(로비에서 진영을 바꿔 들어간 경우)
아무것도 저장하지 않는다. 틀린 승리 팀을 넣으면 이후 팀 밸런싱까지 오염되기
때문이다. 그럴 때는 버튼으로 확정한다.

### 전적 파일 받기

내전은 사설 게임이라 Riot 공개 API(match-v5)로는 받을 수 없다. 대신 **클라이언트가 켜져
있는 동안 열려 있는 로컬 API(LCU)** 에서 직접 뽑는다.

#### 윈도우: 배치 파일 (권장)

`export_custom_matches.bat` 을 클라이언트가 켜진 상태에서 더블클릭하면 된다.
Python 도 추가 설치도 필요 없다. 윈도우 10 이상이면 `curl` 과 PowerShell 이 기본 탑재다.

```
  사설 게임 목록
  ----------------------------------------
    1) 08/26 14:37  (45분)
    2) 08/26 15:20  (33분)
    3) 08/26 15:31  (4분 [중단됨])
  ----------------------------------------

  받을 경기 번호 (그냥 Enter 면 1번): 2
```

고른 경기를 옆에 `custom_matches.json` 으로 저장한다. 추가 게임을 돌리면 한 세션에
여러 판이 쌓여 가장 최근 것이 원하는 판이 아닐 수 있어 골라 받게 했다.

lockfile 경로를 추측하지 않고 **실행 중인 프로세스의 명령줄**에서 포트와 토큰을 읽는다.
설치 드라이브가 제각각이고 클라이언트가 파일을 잠그기도 해서다.

#### 손으로 받기

1. 클라이언트에 로그인한 채로 `lockfile` 을 연다. `LeagueClient:<pid>:<포트>:<비밀번호>:https`
   가 콜론으로 이어져 있다. 설치 위치를 바꾸지 않았다면
   - macOS: `/Applications/League of Legends.app/Contents/LoL/lockfile`
   - Windows: `C:\Riot Games\League of Legends\lockfile`
2. 그 포트로 매치 히스토리를 받는다. 아이디는 `riot` 고정이고, 자체 서명 인증서라 `-k` 가 필요하다.

```bash
curl -sk -u "riot:<비밀번호>" \
  "https://127.0.0.1:<포트>/lol-match-history/v1/products/lol/current-summoner/matches?begIndex=0&endIndex=20" \
  | jq '[.games.games[] | select(.gameType == "CUSTOM_GAME")]' > custom_matches.json
```

응답은 경기 배열이 `games.games` 안에 들어 있다. 배열과 경기 하나 모두 받는다.
경기 한 판의 예시는 `tests/data/first_custom_matches.json` 이다.

[purarue/lolexport](https://github.com/purarue/lolexport) 처럼 공개 API 를 쓰는 도구는
솔랭·일반만 받아오고 사설 게임이 아예 나오지 않아 이 파일로는 쓸 수 없다.

#### 나중에 채우기

버튼으로만 결과를 넣었어도 나중에 파일을 구하면 `/전적보완 내전번호` 로 채울 수 있다.
어느 내전이 비어 있는지는 `/내전기록` 에서 굵게 표시된다. 승패는 이미 기록된 것을
쓰고, 파일이 그와 다른 말을 하면 거절한다.

### 부계정

본계정이 정지되어 부계정으로 뛰는 경우가 있다. `/부계정등록 게임이름#태그` 로 여러 개
등록해두면 전적 파일에서 그 사람을 알아본다.

- **매칭에만 쓴다.** 솔랭 티어·승률·최근 폼은 지금처럼 본계정에서만 받아온다.
- 부계정으로 뛴 내전의 KDA·CS·딜·라인은 그 사람 기록으로 그대로 들어간다.
- **이미 누가 쓰고 있는 Riot ID 는 등록할 수 없다.** 남의 계정을 자기 부계정으로 걸어
  성적을 가져가지 못하게 막는다(본계정·부계정 통틀어 유일).
- 등록할 때 Riot API 로 실존 여부를 확인하고, 계정이 알려주는 정식 표기로 저장한다.
- Riot ID 를 바꾼 사람도 옛 이름을 부계정으로 남겨두면 예전 기록이 계속 맞는다.

### 모집 삭제

로비의 **삭제** 버튼으로 누구나 모집을 지울 수 있다. 참가자·관전자까지
함께 지워지므로 전적 집계에는 남지 않고, 곧바로 `/내전`으로 다시 모집할 수 있다.

### 능력 평가

랭크나 KDA 로는 잡히지 않는 것만 사람이 매긴다. `/능력평가 @사람` 으로 서버 인원
누구나 1~10 을 준다. 자기 자신은 매길 수 없고, **여러 명이 매기면 평균**을 쓴다.

**1 이 기본값이고 위로만 올라가는 가산점이다.** 잘한다고 생각하면 더 주고,
평범하면 1 을 준다. 낮게 준다고 감점이 되지는 않는다.

| 항목 | 성격 | 팀 짜기에서 |
|---|---|---|
| **메인오더** | 팀당 한 명이면 되는 배타적 자원 | 점수에 더하지 않고 **상위 2명을 서로 다른 팀**에 둔다 |
| **오더수행** | 많을수록 좋은 가산 자원 | 점수에 그대로 더한다 |
| **챔피언폭** | 가산 자원 | 점수에 더한다. 계정 숙련도와 평균낸다 |

오더를 둘로 나눈 이유는 성질이 반대이기 때문이다. 한 숫자로 묶으면 오더를 *수행*
하는 사람까지 갈라 놓게 되고, 매기는 사람도 무엇을 넣어야 할지 모른다.

- **한 명만 매겨도 바로 반영한다.** 서로 아는 사람이 많지 않아 여러 명을 기다리면
  값이 영영 안 채워진다. 대신 뒤에서 말하는 판수 감쇠가 그 값을 오래 두지 않는다.
- 내전 판수가 쌓일수록 힘이 줄어, 10판이 되면 완전히 빠지고 실제 기록만 남는다.
  잠그지 않고 자연히 사라지게 한 이유는, 한 판만 뛰어도 영구히 못 고치는 규칙이
  되면 표본이 없는 채로 값이 굳기 때문이다.

#### 챔피언폭은 계정 숙련도도 함께 본다

`/전적등록`·`/전적갱신` 때 챔피언 숙련도를 받아, **가장 많이 판 챔피언 대비 절반
이상인 챔피언이 몇 개인지**로 폭을 잰다. 내전에서는 한 사람에게 1~2챔프를
저격밴하므로, 폭의 실질적인 의미는 주력이 잘렸을 때 대신 꺼낼 카드가 몇 장이냐다.
절대량이 아니라 비율로 보기 때문에 플레이량이 적은 사람도 불리해지지 않는다.

시즌 솔랭이 40판에 못 미치면 그 숙련도가 지금도 유효한지 확인할 길이 없어 가산분을
깎는다. 원트릭은 가산이 없을 뿐 깎이지는 않는다.

### 종합 점수와 10판 전환

`/랭크전적` 의 종합 점수는 팀을 가를 때 쓰는 값과 **같은 경로로 계산한다.** 티어(40%) ·
라인(20%) · 최근 폼(15%) · KDA(10%) · 내전 승률(10%) · 내전 순위(10%) · 챔피언폭(5%) ·
오더수행(5%) 의 가중 평균이고, 없는 요소의 가중치는 나머지에 재분배된다. 언랭이라고
0점을 채우지 않는다는 뜻이다.

**내전을 10판 치르면 솔랭에서 온 지표가 물러난다.** 티어·라인·최근 폼·KDA 의 가중치가
판수에 따라 줄어들어 10판에서 0 이 되고, 내전 기록만 남는다. 그만큼 뛴 사람은 솔랭
티어보다 내전에서 실제로 한 것이 더 잘 설명한다.

내전 지표가 하나도 없으면 전환하지 않는다. 넘겨줄 곳이 없는데 솔랭 지표를 빼면
남는 게 없기 때문이다.

> 승률만으로 전환하지 않는 이유가 있다. 밸런서가 팀을 잘 맞출수록 모두의 내전 승률이
> 50% 로 수렴해 사람을 가르지 못하게 된다. 그래서 `/오더채점` 이 매기는 **판별 순위**를
> 함께 쓴다. 순위는 팀이 균형 잡혀 있어도 판마다 갈리므로 밸런서가 지우지 못한다.

### 내전 라인별 지표

`/내전전적` 은 op.gg e스포츠 선수 기록과 같은 항목을 보여준다. 첫 줄이 지표 이름,
둘째 줄이 전체 합계, 그 아래가 많이 간 라인 순서다.

- 라인은 전적 파일의 실제 라인(`timeline.lane`/`role`)으로 묶고, 읽을 수 없으면 봇이
  배정한 라인으로 대신한다.
- 분당 지표는 경기 시간 **합**으로 나눈다. 경기별 평균이 아니라서 긴 경기가 과대
  반영되지 않는다.
- `DPGR = DPM / GPM` — 먹은 골드 대비 얼마나 딜을 넣었는지 보는 가성비 지표다.
- 경기 시간이 없는 기록(버튼으로만 확정한 내전)은 분당 지표를 낼 수 없어 빠진다.

폭이 넓어 기본/세부 두 덩이로 나눠 보여준다.

```
라인  경기  승  패    승률   KDA    킬  데스  어시
전체    44  23  21   52.3%  4.50   4.0   2.0   5.0
미드    30  18  12   60.0%  4.50   4.0   2.0   5.0

라인     DPM    DTPM     GPM  CSPM  DPGR   첫킬  첫포탑  와드
전체   600.0   500.0   400.0  9.00  1.50  13.3%   20.0%  10.0
미드   600.0   500.0   400.0  9.00  1.50  13.3%   20.0%  10.0
```

### 관전자

로비의 **관전** 버튼으로 등록한다. `/전적등록` 없이 Discord 계정만 있으면 되고,
10명 정원에는 들어가지 않는다. 참가 중인 사람이 관전을 누르면 거절되지만
(자리 하나가 걸린 문제라 직접 취소하게 한다), 관전 중인 사람이 참가를 누르면
자동으로 옮겨진다.

### MVP 투표

결과가 확정되면 결과 메시지에 **MVP 뽑기** 버튼이 붙는다. **이긴 팀과 관전자**가
그 판에서 제일 잘한 사람을 한 명 고른다. 본인은 후보에서 빠지고, 다시 고르면 표가
옮겨진다.

진 팀에 투표권을 주지 않는 이유는 감정이 섞이거나 기권이 많아지기 때문이다.
동점이면 관전자 표로 가르고, **그래도 안 갈리면 MVP 를 두지 않는다.**

받은 MVP 횟수는 `/랭크전적`에 나온다. 봇을 재시작해도 최근 20개 내전의 버튼은
다시 살아난다.

> 예전에는 9명에게 1~10 을 매겼는데 아무도 끝까지 하지 않았다(한 판에 3~7명만
> 참여했고, 그 사람들도 9명 중 6~8명만 매겼다). 한 번 누르면 끝나는 쪽이 실제로
> 모인다.

### 음성 대본으로 판별 평가

`/오더채점` 에 A팀·B팀 음성 대본(`.txt`)을 첨부하면, 대본과 전적을 함께 읽어
**팀 안에서의 순위(1~5위)** 와 메인오더 점수를 매긴다. 관전자 대본은 선택이고
맥락 참고용으로만 쓴다.

절대 점수가 아니라 순위인 이유는, "7점"은 판마다 기준이 흔들리지만 "5명 중 2등"은
그 판 안에서만 비교하므로 흔들리지 않기 때문이다. 누적할 때도 평균 순위가 평균
점수보다 안정적이다.

- 대본 형식은 `[00:12:03] 이름: 대사` 다. 형식에 안 맞는 줄은 건너뛴다.
- **화자를 특정하지 못하면 그 사람은 건너뛴다.** 잘못 붙이면 남의 플레이가 그 사람
  기록이 되어 아무 데이터도 없는 것보다 나쁘다.
- 한 팀에서 순위가 겹치면 그 팀은 통째로 버린다. 2등이 둘이면 나머지 등수의 의미도
  무너진다. 한 명이 빠지는 것은 괜찮다.
- 점수마다 **근거가 된 실제 대사**를 함께 남긴다.
- AI 가 이긴 팀 1등으로 꼽은 사람과 MVP 투표를 대조해 정확도를 잰다. 이긴 팀 5명 중
  하나이므로 찍으면 20% 다. 이 숫자는 채점할 때 로그로만 남긴다.

메인오더 점수는 동료평가와 **같은 무게로 섞는다.** 대본은 누가 지시했는지는 보지만
게임 상황을 볼 수 없어 그 콜이 좋았는지는 모르기 때문이다.

### 티어 엠블럼

`/랭크전적` 은 `assets/ranks/<티어>.png` 를 첨부해 임베드 썸네일로 띄운다. 외부 링크를
쓰지 않아 인터넷 사정이나 링크 만료와 무관하다. 모르는 티어나 언랭이면 `unranked.png`
를 쓴다. 파일을 더 좋은 것으로 바꾸고 싶으면 같은 이름으로 덮어쓰면 된다.

## 개발

```bash
venv/bin/pip install -r requirements-dev.txt
venv/bin/python -m pytest
```

테스트는 인메모리 SQLite를 쓰므로 `.env` 없이도 돌아간다.

스키마를 바꿨으면 마이그레이션을 만든다:

```bash
venv/bin/alembic revision --autogenerate -m "설명"
```

## 문제가 생기면

| 증상 | 확인 |
|---|---|
| 기동하자마자 `ValidationError` | `.env`에 `DISCORD_TOKEN` / `RIOT_API_KEY`가 있는지 |
| 슬래시 명령이 안 보임 | `.env`의 `DISCORD_GUILD_ID`에 해당 서버 ID가 있는지, 봇이 그 서버에 초대됐는지 |
| 명령이 두 번 응답 | 같은 토큰으로 봇이 두 곳에서 켜져 있다 |
| `/전적등록`만 실패 | Riot 키 만료. 개발용 키는 24시간마다 갱신해야 한다 |
