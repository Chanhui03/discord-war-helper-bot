# 내전 도우미

LoL 내전 참가자를 모아 5:5 팀을 자동으로 짜주는 Discord 봇. 내 PC에서 직접 돌린다.

## 준비

Python 3.9 이상. 저장소 루트에서:

```bash
python3 -m venv venv
venv/bin/pip install -r requirements.txt
```

`.env.example`을 `.env`로 복사해 채운다.

```bash
cp .env.example .env
```

| 항목 | 설명 |
|---|---|
| `DISCORD_TOKEN` | [Discord 개발자 포털](https://discord.com/developers/applications)의 봇 토큰 |
| `RIOT_API_KEY` | [Riot 개발자 포털](https://developer.riotgames.com). 개발용 키는 24시간마다 만료되므로 `/전적등록`이 하루 뒤 실패하면 새로 발급받는다 |
| `DISCORD_GUILD_ID` | 슬래시 명령을 즉시 등록할 서버 ID. 쉼표로 여러 개. 비우면 전역 등록이라 반영에 최대 1시간 걸린다 |

## 실행

```bash
venv/bin/python -m app.main
```

`내전도우미#8506 로그인 완료`가 보이면 성공. Discord에서 `/ping`으로 확인한다.

DB는 저장소 루트의 `war_helper.db`(SQLite) 하나다. 첫 실행 때 자동으로 만들어지고,
이후 기동할 때마다 스키마를 최신으로 맞춘다(`app/main.py` 의 `migrate()`). 별도 설치가
필요 없다.

끄려면 `Ctrl+C`. **봇은 이 프로세스가 떠 있는 동안에만 응답한다** — 내전을 할 때 켜두면 된다.
껐다 켜도 기록은 남고, 진행 중이던 내전의 버튼도 다시 살아난다(`restore_views()`).

Discord 공지로 붙여넣을 사용자용 안내는 [discord_notice.md](discord_notice.md) 에 있다.

## 명령

| 명령 | 하는 일 |
|---|---|
| `/전적등록 게임이름#태그` | Riot 계정을 연결하고 랭크·최근 20경기를 받아온다 |
| `/전적갱신` | 등록한 계정의 전적을 다시 받아온다 (Riot ID 를 다시 입력하지 않는다) |
| `/라인설정` | 선호라인 1순위 / 2순위 / 기피라인을 고른다 |
| `/랭크전적` | 솔로랭크 전적과 라인별 지표를 본다 |
| `/내전전적` | 내전 라인별 지표를 본다 (전체 한 줄 + 많이 간 라인 순) |
| `/능력평가 @사람` | 오더능력 / 챔피언폭을 1~10 으로 매긴다 |
| `/등록목록` | 등록된 게이머를 최근 갱신 날짜와 함께 본다 |
| `/내전` | 참가자와 관전자를 모집한다 |
| `/결과` | 승리 팀을 확정한다. 사설 전적 JSON 을 첨부하면 개인 성적까지 기록한다 |
| `/ping` | 응답 속도 확인 |

### 누가 무엇을 할 수 있나

**전부 서버 인원 누구나 할 수 있다.** 모집 열기·팀 생성·자리 교환·모집 삭제·결과
확정에 권한 제한이 없다. 친목 내전이라 관리자가 자리에 없다고 멈추는 쪽이 더 불편하다.

다만 **결과 확정은 되돌릴 수 없다.** 잘못 누르면 그 내전의 승패가 그대로 남아 내전
승률과 MVP 집계에 들어간다.

### 팀 수정

팀 생성 뒤 메시지에 붙는 **자리를 바꿀 두 명을 고르세요** 메뉴로 누구나 배정을 손볼 수
있다. 고른 두 사람의 팀과 라인을 통째로 맞바꾸므로 팀마다 라인 5개는 그대로 유지된다.
바꿀 때마다 밸런스 점수를 같은 기준으로 다시 계산해 보여준다.

### 사설 전적 기록

`/결과`에 LoL 클라이언트에서 받은 매치 히스토리 JSON 을 첨부하면 승패뿐 아니라
KDA / CS / 딜 / 받은 딜 / 골드 / 와드 / 첫킬 / 첫포탑과 경기 시간까지 저장하고,
`/내전전적`의 라인별 지표에 반영한다. 첨부하지 않으면
지금처럼 버튼으로 승리 팀만 고르면 된다.

파일 안에 경기가 여러 개 있어도 되고, 참가자 10명이 모두 들어 있는 가장 최근
경기를 자동으로 고른다. 중단된 경기(`endOfGameResult`가 `Abort_`로 시작)는 건너뛴다.

**참가자는 게임이름#태그로 맞춘다.** 클라이언트가 내주는 기록은 `puuid`,
`accountId`, `summonerName` 이 모두 익명화되어 있어 다른 식별자를 쓸 수 없다.
`/전적등록`에 쓴 Riot ID 와 다른 계정으로 내전을 뛰었다면 맞출 수 없고, 그때는 누가
안 맞았는지 알려준다.

봇이 짠 A/B 팀과 파일의 승패가 어긋나면(로비에서 진영을 바꿔 들어간 경우)
아무것도 저장하지 않는다. 틀린 승리 팀을 넣으면 이후 팀 밸런싱까지 오염되기
때문이다. 그럴 때는 버튼으로 확정한다.

### 모집 삭제

로비의 **삭제** 버튼으로 누구나 모집을 지울 수 있다. 참가자·관전자까지
함께 지워지므로 전적 집계에는 남지 않고, 곧바로 `/내전`으로 다시 모집할 수 있다.

### 오더능력과 챔피언폭

랭크나 KDA 로는 잡히지 않는 두 가지만 사람이 매긴다. `/능력평가 @사람` 으로 서버 인원
누구나 1~10 을 준다. 자기 자신은 매길 수 없고, **여러 명의 평균**을 쓴다.

- 평가가 3명 미만이면 반영하지 않는다. 한 사람이 남의 값을 정해버리지 못하게 한다.
- 내전 판수가 쌓일수록 힘이 줄어, 10판이 되면 완전히 빠지고 실제 기록만 남는다
  (`scoring.trait_score`). 잠그지 않고 자연히 사라지게 한 이유는, 한 판만 뛰어도
  영구히 못 고치는 규칙이 되면 표본이 없는 채로 값이 굳기 때문이다.
- **챔피언폭**은 설계서 6장에서 비어 있던 `mastery` 가중치(0.05) 자리를 채운다.
- **오더능력**은 점수에 더하지 않는다. 오더는 팀당 한 명이면 되는 자원이라 더하면
  '오더 둘이 한 팀'이 최적해가 된다. 대신 **상위 2명을 서로 다른 팀에 두는 제약**으로
  쓴다. 기피 라인 금지와 부딪히면 기피 쪽을 먼저 지키고, 못 지키면 팀 구성 메시지에
  알린다.

현재 값과 평가 인원은 `/내전전적` 아래쪽에서 볼 수 있다.

### 내전 라인별 지표

`/내전전적` 은 op.gg e스포츠 선수 기록과 같은 항목을 보여준다. 첫 줄이 지표 이름,
둘째 줄이 전체 합계, 그 아래가 많이 간 라인 순서다.

- 라인은 전적 파일의 실제 라인(`timeline.lane`/`role`)으로 묶고, 읽을 수 없으면 봇이
  배정한 라인으로 대신한다.
- 분당 지표는 경기 시간 **합**으로 나눈다. 경기별 평균이 아니라서 긴 경기가 과대
  반영되지 않는다.
- `DPGR = DPM / GPM` — 먹은 골드 대비 얼마나 딜을 넣었는지 보는 가성비 지표다.
- 경기 시간이 없는 기록(버튼으로만 확정한 내전)은 분당 지표를 낼 수 없어 빠진다.

폭이 넓어 기본/세부 두 덩이로 나눠 보여준다.

```
라인  경기  승  패    승률   KDA    킬  데스  어시
전체    44  23  21   52.3%  4.50   4.0   2.0   5.0
미드    30  18  12   60.0%  4.50   4.0   2.0   5.0

라인     DPM    DTPM     GPM  CSPM  DPGR   첫킬  첫포탑  와드
전체   600.0   500.0   400.0  9.00  1.50  13.3%   20.0%  10.0
미드   600.0   500.0   400.0  9.00  1.50  13.3%   20.0%  10.0
```

### 관전자

로비의 **관전** 버튼으로 등록한다. `/전적등록` 없이 Discord 계정만 있으면 되고,
10명 정원에는 들어가지 않는다. 참가 중인 사람이 관전을 누르면 거절되지만
(자리 하나가 걸린 문제라 직접 취소하게 한다), 관전 중인 사람이 참가를 누르면
자동으로 옮겨진다.

### 평점과 MVP

결과가 확정되면 결과 메시지에 **평점 남기기** 버튼이 붙는다. 그 내전의 참가자와
관전자가 1~10점을 매기고, **평균이 가장 높은 사람이 MVP**가 된다. 동점이면 표를
더 많이 받은 쪽이 이긴다. 받은 MVP 횟수는 `/랭크전적`에 나온다.

참가자는 본인을 뺀 9명을, 관전자는 10명 전부를 평가한다. 관전자는 Riot 계정이
없을 수 있어 평가자를 `player_id` 가 아니라 Discord 사용자로 저장한다.

평점은 나중에 더 들어올 수 있어서 MVP 를 컬럼에 저장하지 않고 `match_ratings`
에서 그때그때 계산한다. 내전 승패 집계(`custom_records`)와 같은 이유다.

봇을 재시작해도 최근 20개 내전의 평점 버튼은 다시 살아난다.

## 개발

```bash
venv/bin/pip install -r requirements-dev.txt
venv/bin/python -m pytest
```

테스트는 인메모리 SQLite를 쓰므로 `.env` 없이도 돌아간다.

스키마를 바꿨으면 마이그레이션을 만든다:

```bash
venv/bin/alembic revision --autogenerate -m "설명"
```

## 문제가 생기면

| 증상 | 확인 |
|---|---|
| 기동하자마자 `ValidationError` | `.env`에 `DISCORD_TOKEN` / `RIOT_API_KEY`가 있는지 |
| 슬래시 명령이 안 보임 | `.env`의 `DISCORD_GUILD_ID`에 해당 서버 ID가 있는지, 봇이 그 서버에 초대됐는지 |
| 명령이 두 번 응답 | 같은 토큰으로 봇이 두 곳에서 켜져 있다 |
| `/전적등록`만 실패 | Riot 키 만료. 개발용 키는 24시간마다 갱신해야 한다 |
